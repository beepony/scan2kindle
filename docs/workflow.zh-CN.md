# 扫描 PDF 转 Kindle 电子书流程总结

这份文档记录 `scan2kindle` 的完整处理流程，也总结了在一批真实中文扫描期刊上的实践经验。

## 1. 先判断 PDF 类型

扫描 PDF 大致有三种：

- **纯图片扫描**：页面里没有可复制文字，必须做文字识别。
- **带隐藏文字层的扫描**：可以复制文字，但旧文字层可能错字较多、顺序不稳定。
- **跨页扫描**：一个 PDF 页面里包含左右两页书。

为了让不同年代的文件效果一致，本工具默认对所有页面重新识别，不依赖 PDF 原有文字层。

如果同一本书已经有质量较好的正式 EPUB，应优先使用正式 EPUB。由 PDF 自动导出的 Word 文件常有断行、额外空格和缺少目录的问题，不一定比重新识别更好。

## 2. 渲染页面

每页渲染成灰度图，默认高度为 2200 像素。这个尺寸能兼顾中文小字识别准确度和处理速度。

当页面宽度明显大于高度时，程序会在中间区域寻找空白最多的位置，把它拆成左右两页。

## 3. 离线文字识别

识别使用 macOS Vision：

- 默认语言：`zh-Hans,en-US`
- 输出每一行文字、可信度和坐标
- 每页结果单独缓存成 JSON
- 中断后再次运行，会跳过已识别页面

我们也测试过 PaddleOCR。它准确，但在纯 CPU 环境下较慢；在 Apple Silicon Mac 上，Vision 对这批中文扫描件更快，也更稳定。

## 4. 重建可阅读文本

单纯按识别顺序拼接文字会产生很多问题，所以程序会利用文字坐标重建版面：

1. 去除页面顶部和底部重复出现的页眉、页码。
2. 查找中间空白栏，判断单栏或双栏。
3. 合并同一行被识别成多个片段的文字。
4. 根据缩进、行距和上一行长度判断段落。
5. 下一页开头没有缩进时，把它接到上一页段落后面。
6. 识别比正文字号更大的标题。
7. 裁出大面积非文字区域作为插图，并识别附近的小字号图片说明。
8. 封面、目录和文字很少的页面保留为整页图片。

## 5. 生成目录

目录是 Kindle 阅读体验的关键。程序按以下顺序尝试：

1. **解析有页码的目录页**：读取标题、作者和印刷页码。
2. **推算页码偏移**：比较页面底部或顶部的印刷页码和 PDF 实际页号，找到文章开始的位置。
3. **匹配无页码目录**：如果目录只有标题，就到正文中寻找同名的大字号标题。
4. **识别文章首页**：如果书中没有目录页，就寻找“大标题 + 作者 + 正文从页面中部开始”的页面。
5. **最后兜底**：使用正文中检测到的大标题分章。

一个容易出错的地方：正文里也可能出现“目录”两个字。程序只把单独成行的“目录”或“Contents”当作目录标题，避免把启事、简介等页面误当成目录。

## 6. 输出电子书

程序直接写出 EPUB 3，包括：

- 封面和整页图片
- 每篇文章或章节单独成文件
- 可跳转的导航目录
- 适合中文阅读的首行缩进、行距和图片样式

安装 Calibre 后，程序会把 EPUB 继续转换为 AZW3。默认使用 `kindle_pw3` 输出配置，可通过 `--kindle-profile` 修改。

## 7. 质量检查

建议按以下顺序检查：

1. 先用 `--pages 1-30` 试转几本不同排版的书。
2. 查看 `conversion-report.csv`：
   - `chars` 明显偏少：可能识别失败或页面范围不完整。
   - `toc_entries` 很少：需要检查目录页或标题样式。
   - `low_conf` 很高：扫描质量可能较差。
3. 用 EPUBCheck 检查 EPUB 格式。
4. 在 Kindle 或 Calibre 阅读器中抽查目录跳转、段落和插图。
5. 修改规则后使用 `--force` 重新生成；因为有缓存，通常不需要重新识别。

## 8. 实践结果

在一批 121 个中文扫描期刊 PDF（约 4.7 GB）上：

- 识别速度约每页 0.9 秒。
- 一本约 320 页的书通常需要 0.7–0.8 分钟。
- 两份字节完全相同的重复 PDF 被自动跳过。
- 生成的 EPUB 均通过 EPUBCheck。
- 有页码目录、无页码目录和缺少目录页的书都能生成可跳转导航。

## 9. 适用边界

这个工具最适合以正文为主的扫描书、期刊、论文集和资料。复杂教材、表格、公式、漫画、竖排古籍和杂志拼贴版面更适合保留 PDF，或在转换后人工校对。
